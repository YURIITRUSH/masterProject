# Науково-технічна документація: HIL-комплекс нейро-адаптивного керування DC-двигуном

## 1. Загальна архітектура системи
Програмно-апаратний комплекс (Hardware-in-the-Loop) побудований за трирівневою архітектурою, що розділяє жорсткий реальний час, збір даних та інтелектуальну частину (цифровий двійник і нейромережу).

1. **Нижній рівень (Hard Real-Time):** Мікроконтролер Arduino UNO (файл `projectMain.ino`). Зчитує енкодер (апаратні переривання) та датчик струму/напруги INA219, формує ШІМ і реалізує каскадний закон керування PID-PBC.
2. **Верхній рівень (Soft Real-Time):** Хост-ПК (Python, файл `main.py`). Керує процесами збору телеметрії, калібрування, навчання ШІ та проведення HIL-тестів. Реалізований як єдиний CLI-інструмент (інтерфейс командного рядка).
3. **Рівень ШІ:** Навчання нейромережі TensorFlow на даних цифрового двійника та динамічне оновлення коефіцієнтів `Kp, Ki, Kd` (Neural Gain Scheduling) у реальному часі.

**Потік даних:** Мікроконтролер надсилає CSV-рядок із **семи полів** через USB-Serial (115200 бод) -> Python-скрипт пише його у `logs/telemetry_*.csv` та будує графіки.

## 2. Апаратна частина
### 2.1. Схема з'єднань (Pinout)
*   **Керування:** Драйвер L298N (ENA — D5 для ШІМ, IN1 — D7, IN2 — D4 для напрямку).
*   **Зворотний зв'язок:** Енкодер (C1 — D2, C2 — D9, апаратні переривання).
*   **Моніторинг:** INA219 на I2C (SDA — A4, SCL — A5, адреса 0x40). Шунт увімкнено послідовно з мотором, що дозволяє вимірювати реальну напругу безпосередньо на обмотках.
*   **Живлення:** Силова частина (L298N) — 12 В. Логіка (Arduino, INA219) — від USB. Земля спільна.

### 2.2. Параметри одометрії (Критично важливо)
Двигун N20 має магнітний енкодер (7 імпульсів/оберт) та редуктор 1:150. Під час експериментів було встановлено, що реальна кількість тіків на один оберт вихідного валу становить **2100**, а не 4200 (що відповідає x2 декодуванню або редуктору 1:75). У прошивці встановлено `TICKS_PER_REV = 2100.0f`. У прошивці застосовано time-based експоненційний фільтр швидкості (τ = 40 мс) для усунення шумів квантування.

### 2.3. Фізичні обмеження
*   **Максимальна швидкість:** Експериментально встановлено, що через падіння напруги на драйвері L298N (близько 2 В) та сухе тертя редуктора, **максимальна досяжна швидкість становить ≈ 18.3 рад/с** (при 100% ШІМ). Нейромережа навчена на діапазоні 3–21 рад/с.
*   **Ефективна напруга (V_supply):** Оскільки INA219 вимірює напругу після драйвера, значення `V_supply ≈ 11.2 В` використовується як реальна напруга живлення мотора.

## 3. Встановлення та налаштування комплексу

Процес розгортання програмно-апаратного комплексу складається з кількох етапів: підготовки апаратного забезпечення, прошивки мікроконтролера та налаштування середовища хост-ПК.

### 3.1. Підготовка апаратного забезпечення
Перед початком роботи необхідно зібрати схему згідно з розділом 2.1 та звернути увагу на такі критичні моменти:
1.  **Живлення:** Підключіть силову частину (драйвер L298N) до джерела 12V. Логіку Arduino та датчик INA219 живіть від USB (5V). **Обов'язково з'єднайте GND блока живлення 12V із GND плати Arduino.**
2.  **Джампери на L298N:**
    *   Джампер **5V_EN** має бути встановлений (це активує живлення датчиків Холла енкодера від драйвера).
    *   Джампер **ENA** необхідно зняти (це дозволить керувати швидкістю через зовнішній ШІМ-сигнал з піна D5).
3.  **Датчик INA219:** Переконайтеся, що шунт підключено послідовно між виходом драйвера OUT1 та обмоткою двигуна M1.

### 3.2. Налаштування мікроконтролера (Arduino)
1.  Встановіть **Arduino IDE** (версія 2.x або новіша).
2.  У менеджері бібліотек (Sketch → Include Library → Manage Libraries) знайдіть та встановіть бібліотеку **`Adafruit INA219`**.
3.  Відкрийте файл прошивки `arduino/projectMain/projectMain.ino`.
4.  Перевірте правильність пінів у просторі імен `Config` (за замовчуванням ENA=5, IN1=7, IN2=4, Encoder=2,9).
5.  Виберіть вашу плату (Tools → Board → Arduino UNO) та відповідний COM-порт.
6.  Натисніть **Upload** (Завантажити).
7.  **⚠️ КРИТИЧНО ВАЖЛИВО:** Після завершення завантаження **закрийте Serial Monitor** в Arduino IDE. Якщо він залишиться відкритим, він заблокує COM-порт, і Python-скрипт не зможе підключитися до Arduino.

### 3.3. Налаштування середовища хост-ПК (Python)
1.  Встановіть **Python 3.10+** (рекомендовано 3.13, оскільки він найкраще сумісний із сучасними версіями TensorFlow).
2.  Відкрийте термінал (PowerShell або CMD) у кореневій папці проєкту та створіть віртуальне середовище:
    ```powershell
    python -m venv tf_env
    ```
3.  Активуйте віртуальне середовище:
    *   *Windows:* `.\tf_env\Scripts\Activate.ps1`
    *   *macOS/Linux:* `source tf_env/bin/activate`
4.  Оновіть менеджер пакетів та встановіть необхідні бібліотеки:
    ```powershell
    pip install --upgrade pip
    pip install -r requirements.txt
    ```
    *(Файл `requirements.txt` містить: tensorflow, pandas, scipy, matplotlib, numpy, pyserial).*

### 3.4. Перевірка конфігураційних файлів
У папці `ai/` знаходиться файл `config.json`. Перед першим запуском переконайтеся, що параметри в ньому адекватні:
*   `V_supply`: реальна напруга на моторі (зазвичай 10.3–11.2 В залежно від блока живлення).
*   `R` та `Ke`: фізичні параметри мотора. 
    *   *Примітка:* Якщо після калібрування ви бачите аномально високий опір (наприклад, `R = 18.8 Ом`), це може бути спричинено опором з'єднувальних дротів, внутрішнім опором L298N та недосконалістю вимірювань на дуже низьких струмах. Модель з таким опором все одно працює коректно, але для ідеальної фізики рекомендується перевірити контакти.

### 3.5. Порядок першого запуску
Після успішного налаштування середовища рекомендується виконати таку послідовність команд для перевірки системи:
1.  **Збір базових даних:** `python main.py collect --scenario scenario.txt`
2.  **Калібрування моделі:** `python main.py calibrate`
3.  **Навчання ШІ:** `python main.py train --max-target 21.0`
4.  **Тест із нейромережею:** `python main.py ai --target 15.0`

### 3.6. Вирішення типових проблем (Troubleshooting)
*   **`ConnectionError: Arduino не знайдено`**: Перевірте USB-кабель (він має бути з підтримкою передачі даних) та драйвер CH340. Вкажіть порт вручну: `--port COM5`.
*   **`serial.serialutil.PortNotOpenError`**: COM-порт зайнятий іншою програмою. Закрийте Serial Monitor в Arduino IDE або інші термінали.
*   **`ModuleNotFoundError: No module named 'tensorflow'`**: Ви не активували віртуальне середовище `tf_env`. Виконайте `.\tf_env\Scripts\Activate.ps1`.
*   **Мотор не рухається при команді `w 10`**: Перевірте живлення 12V. Якщо ШІМ менше 12 (мертва зона), мотор не зрушить. Перевірте, чи подається напруга на L298N.
*   **Нейромережа видає однакові коефіцієнти**: Перевірте, чи правильно відкалібровано `config.json`. Якщо `R` або `Ke` мають некоректні значення, модель TensorFlow буде працювати погано.

## 4. Математична модель та закон керування
Нижній рівень реалізує каскад: зовнішній PID-контур за швидкістю формує бажаний струм `i_ref`, внутрішній PBC-контур (Passivity-Based Control) формує напругу `u`.

1. **Зовнішній контур (PID):**
   *   Інтегральна складова має вікно `|e| < 6.0 рад/с`. Поза вікном інтеграл згасає, що запобігає windup.
   *   Похідна фільтрується (τ = 20 мс).
2. **Внутрішній контур (PBC):** `u = ke * target + R * i_ref - Rd * (current_I - i_ref)`.
3. **Feedforward тертя:** Додається константа `0.3 + 0.02*|target|` для подолання зони нечутливості мотора (stick-slip).
4. **Slew Rate Limiter:** Обмежує швидкість наростання ШІМ до 1000 ШІМ/с (захист редуктора від різких ударів).

## 5. Програмне забезпечення нижнього рівня (Arduino)
Прошивка `projectMain.ino` об'єктно-орієнтована. Головний цикл `loop()` неблокуючий (працює на `millis()`).

**Формат телеметрії (7 полів):**
`Current_A, Voltage, Omega, Target, PWM, Ticks, dTicks`

**Спеціальні команди:**
*   `w <рад/с>` — задати цільову швидкість (замкнений контур).
*   `turn <тіки> <ШІМ>` — повернути вал на задану кількість тіків (блокує цикл, використовувати лише вручну!).

---

## 6. Програмне забезпечення верхнього рівня (Python `main.py`)
Замість багатьох розрізнених скриптів, розроблено єдиний CLI-контролер (на базі `argparse` та ООП).

**Модулі системи:**
*   `Config` — централізоване зберігання шляхів, меж пошуку `Kp/Ki/Kd` та параметрів за замовчуванням.
*   `DigitalTwin` — математична модель мотора.
*   `SerialManager` — контекстний менеджер для безпечної роботи з COM-портом (гарантує зупинку мотора при `Ctrl+C`).
*   `DataCollector` — збір даних та виконання сценаріїв.
*   `Calibrator` — ідентифікація параметрів.
*   `AITrainer` — генерація даних та навчання TensorFlow.
*   `HILController` — керування мотором у реальному часі.
*   `Analyzer` — візуалізація результатів.

## 7. Цифровий двійник та калібрування
### 7.1. Модель двигуна та чисельна стійкість
Система диференціальних рівнянь:
1. Електрична частина: `L di/dt = u - R*i - Ke*ω`
2. Механічна частина: `J dω/dt = Km*i - Ts*sign(ω) - b*ω`

Використання стандартного розв'язувача `solve_ivp` (RK45) показало його непридатність через жорсткість системи. Тому в `main.py` реалізовано **аналітичне рішення для струму** та **метод Ейлера з підкроками 0.5 мс** для механіки.

### 7.2. Алгоритм калібрування (Поетапний)
Замість сліпої оптимізації, скрипт `calibrate` використовує фізично обґрунтований підхід:
1. **Напруга:** Береться реальна напруга з INA219 при 100% ШІМ.
2. **Електрика (R, Ke):** Використовується **Non-Negative Least Squares (NNLS)** на стаціонарних ділянках руху для знаходження додатних фізичних параметрів.

## 8. Нейро-адаптивне керування (Neural Gain Scheduling)
1. **Генерація даних:** Для цілей від 3 до 21 рад/с цифровий двійник розв'язує задачу оптимізації (Differential Evolution) для пошуку ідеальних `Kp, Ki, Kd`.
2. **Архітектура ШІ:** Нейромережа має **2 входи** (ціль, похибка) та **3 виходи** (Kp, Ki, Kd). Шари: Dense 32 -> Dense 16 -> Dense 3.
3. **HIL-тест:** Скрипт `main.py ai` зчитує телеметрію, формує вектор похибки, проганяє через модель TensorFlow та кожні 100 мс відправляє нові коефіцієнти на Arduino.

## 9. Порядок роботи з комплексом (Workflow)
1. **Збір даних:** `python main.py collect --scenario scenario.txt --plot`
2. **Калібрування:** `python main.py calibrate`
3. **Навчання ШІ:** `python main.py train --max-target 21.0`
4. **HIL-тест (ідеальний):** `python main.py ai --target 15.0 --plot` (Зупинка Ctrl+C).
5. **HIL-тест (насичення):** `python main.py ai --target 21.0 --plot`
6. **Аналіз:** `python main.py analyze --file logs/ai_telemetry_...csv --save logs/fig.png`

## 10. Методика проведення експериментів (Результати)
*   **Тест частоти:** Сценарій `scenario_freq_test.txt` показує, що 10 Гц дає сходинки на ШІМ, 100 Гц — ідеальний баланс, а 500 Гц — шум через обмеження шини I2C датчика INA219.
*   **Ідеальний ШІ:** На цілі 15.0 рад/с нейромережа забезпечує статичну похибку < 0.1 рад/с.
*   **Насичення:** На цілі 21.0 рад/с ШІ видає `Kp=1.138`, але мотор фізично досягає лише 18.3 рад/с (похибка ~2.7 рад/с). Це доводить наявність фізичного обмеження (Actuator Saturation).

## 11. Інженерні вимоги та обмеження
1. **Механічна фіксація:** Корпус N20 має бути жорстко закріплений.
2. **Порядок увімкнення:** Спочатку USB та запуск Python, потім 12 В.
3. **Зупинка:** Команда `s` (надсилається автоматично при виході) вимикає PBC та двигун.
4. **Обмеження цілей:** Не перевищувати 18.3 рад/с (фізична межа).
