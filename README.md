# HIL-КОМПЛЕКС: НЕЙРО-АДАПТИВНЕ КЕРУВАННЯ DC-МОТОРОМ (DIGITAL TWIN + TENSORFLOW)

Цей проєкт є програмно-апаратним комплексом (Hardware-in-the-Loop) для дослідження та автоматичного налаштування каскадного PID-PBC регулятора для мікродвигуна постійного струму N20.

## 🧠 ГОЛОВНА НАУКОВА НОВИЗНА
Розроблено систему **Neural Gain Scheduling**, яка використовує відкалібрований цифровий двійник (Digital Twin) для генерації даних та навчання нейронної мережі (TensorFlow). У реальному часі нейромережа зчитує похибку швидкості та динамічно змінює коефіцієнти `Kp, Ki, Kd` на мікроконтролері, долаючи нелінійність тертя (stick-slip) та фізичні обмеження драйвера.

## 📂 СТРУКТУРА ПРОЄКТУ
- `arduino/projectMain/` — прошивка Arduino (C++), реалізація PID-PBC, обробка Serial-команд.
- `core/` — базові скрипти:
  - `digital_twin.py` — математична модель двигуна (стійка інтеграція Ейлера).
  - `script.py` — збір телеметрії з реального заліза.
- `analysis/` — калібрування двійника (`calibrate_twin.py`, `compare_twin.py`) та аналіз телеметрії (`analyze.py`).
- `ai/` — навчання нейромережі (`ai_train_tf_model.py`) та контролер реального часу (`ai_tf_controller.py`).
- `logs/` — логи телеметрії (CSV) та збережені графіки (PNG).

## 🛠️ АПАРАТНЕ ЗАБЕЗПЕЧЕННЯ
- **Мікроконтролер:** Arduino Uno (або сумісний).
- **Драйвер двигуна:** L298N.
- **Двигун:** N20 з редуктором 150:1 та квадратурним енкодером (4200 тіків/оберт).
- **Датчик струму/напруги:** INA219 (I2C).
- **Живлення:** 12V для мотора, USB для Arduino.

### Схема підключення (Pinout)

| Компонент | Пін Arduino | Примітка |
|---|---|---|
| L298N **ENA** | D5 | PWM |
| L298N **IN1** | D7 | Напрямок |
| L298N **IN2** | D4 | Напрямок |
| Енкодер **A** | D2 | Переривання (INT0) |
| Енкодер **B** | D9 | Переривання |
| INA219 **SDA** | A4 | I2C |
| INA219 **SCL** | A5 | I2C |

> ⚠️ **Важливо:** Обов'язково з'єднайте GND блока живлення 12V та GND Arduino.

## 🚀 ЯК ЗАПУСТИТИ (WORKFLOW)

### Етап 0: Підготовка прошивки
1. Підключіть Arduino та відкрийте `arduino/projectMain/projectMain.ino`.
2. Переконайтеся, що стоять базові коефіцієнти (`Kp=0.4f, Ki=0.1f, Kd=0.002f`), та натисніть **Upload**.
3. **Закрийте Serial Monitor** в Arduino IDE, щоб звільнили COM-порт.

### Етап 1: Збір базових даних (Крок 1)
Очистіть папку `logs` від старих файлів та запустіть збір даних (замініть `COM5` на ваш порт):
```powershell
python core/script.py COM5 --scenario scenario_freq_test.txt
```
*Результат:* у папці `logs/` з'явиться CSV-файл з телеметрією.

### Етап 2: Калібрування цифрового двійника (Крок 2)
```powershell
python analysis/calibrate_twin.py
python analysis/compare_twin.py
```
*Результат:* скрипт підбере фізичні параметри мотора (R, L, Ke, Km, J, Ts, V_supply) та покаже графік збігу реальності з моделлю. 
*Очікуваний результат:* RMSE < 3.0 рад/с.

### Етап 3: Навчання нейромережі (Крок 3)
```powershell
python ai/ai_train_tf_model.py
```
*Результат:* у папці `ai/` з'являться файли `tf_model.keras` та `tf_scaler.pkl`.

### Етап 4: HIL-тест з нейромережею в реальному часі (Крок 4)
> 💡 **Порада:** Переконайтеся, що в `ai/ai_tf_controller.py` цільова швидкість (Target) встановлена на фізично досяжне значення (наприклад, **8.0 рад/с**, а не 15.0).

```powershell
python ai/ai_tf_controller.py COM5
```
*Результат:* нейромережа почне динамічно змінювати `Kp, Ki, Kd`. Похибка (Error) має впасти майже до нуля. Натисніть **Ctrl+C** після стабілізації.

### Етап 5: Аналіз результатів (Крок 5)
Оскільки ШІ зберігає логи з префіксом `tf_`, вкажіть шлях до файлу вручну:
```powershell
python analysis/analyze.py logs/tf_telemetry_ВАШ_ФАЙЛ.csv --save logs/final_ai_result.png
```
*Результат:* у консолі з'явиться звіт з метриками (статична похибка, перерегулювання), а в `logs/` збережеться графік для диплома.

## ⚠️ ВАЖЛИВІ ТЕХНІЧНІ НЮАНСИ (Troubleshooting)
1. **Падіння напруги на L298N:** Модель калібрується з `V_supply ≈ 9.7 В`, хоча INA219 показує 11.1 В. Це нормально, оскільки драйвер L298N "з'їдає" ~1.5-2 В.
2. **Физичні обмеження мотора:** При живленні 12V та ШІМ 255 мотор N20 з редуктором 150:1 видає максимум ~8.9 рад/с. Не ставте ціль 15.0 рад/с для ШІ, інакше буде велика статична похибка.
3. **Інтеграція ODE:** У `digital_twin.py` використовується аналітичне рішення для струму та метод Ейлера для механіки (через жорсткість системи). Стандартний `solve_ivp` (RK45) тут не працює.
